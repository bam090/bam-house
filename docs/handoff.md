# bam-house 인계 문서

작성일: 2026-11-12
작성 시점의 브랜치: `feat/house-scene`

이 문서는 다음 세션이 이전 대화 없이 작업을 이어갈 수 있도록 지금까지 정한 내용과 현재 상태를 정리한 것이다.

## 1. 프로젝트가 무엇인가

방문자가 고양이를 움직여서 3D 공간을 둘러보며 개발자를 소개받는 포트폴리오 사이트다.
이력서와 GitHub 프로필에 링크를 걸어서 채용 담당자가 PDF 포트폴리오를 읽기 전에 먼저 보게 한다.

- 저장소: https://github.com/bam090/bam-house (공개)
- 사용자: 부트캠프 수강 중인 초보 개발자. AI 도구를 적극적으로 쓰는 백엔드 개발자 직무를 목표로 한다.
- 참고 사이트: https://studiomeal.com/ 와 https://rhythm-section.vercel.app/ 와 https://forest-portfolio-pi.vercel.app/

### 강사의 조언에서 나온 기준

- 이 사이트는 가볍게 만든다. 자세한 설명은 PDF 포트폴리오와 GitHub README가 맡는다.
- 프로젝트 패널에는 이름과 한 줄 설명과 만든 이유와 맡은 일 한 문장과 링크만 넣는다.
- 트러블슈팅 같은 긴 내용은 넣지 않는다.

## 4. 지금 동작하는 것

- `npm run dev`를 실행하고 `http://localhost:5173`을 열면 된다.
- WASD로 이동한다. W는 카메라가 보는 방향으로 간다.
- 방향키와 드래그로 시선을 좌우와 위아래로 돌린다. 드래그는 끄는 방향으로 시선이 따라간다.
- 휠로 카메라 거리를 1.8m에서 40m 사이로 바꾼다.
- 스페이스바로 점프한다. 보기용이고 물체 위에 올라가지는 못한다.
- 고양이는 거실과 테라스 안에서만 걷는다. 수영장과 선베드와 유리창은 통과하지 못한다.
- 커서는 Codex가 만든 고양이 발바닥 그림이다.

### 좌표 기준

- 집의 중심이 원점이다. 거실은 x가 -8에서 8이고 z가 -6에서 6이다.
- 테라스는 +z 방향에 있다. 바다도 +z 방향이다.
- 집 뒤쪽 벽은 z가 -6인 면이다. TV를 여기에 건다.
- 숲으로 덮인 언덕은 -z 방향과 멀리 -x 방향에 있다.
- 거실 바닥과 테라스 바닥의 높이가 0이다.

## 6. 검사 방법

```bash
npm run build
```

```bash
node scripts/check-terrain.ts
```

지형이나 식물 배치를 고친 뒤에는 두 명령을 모두 실행한다.
지형 검사는 여덟 가지를 본다.
집 자리가 평평한지와 테라스에서 집 정면의 해변 110m가 땅에 가려지지 않는지와 앞쪽 식물이 눈높이보다 낮은지와 해변 폭과 물속 깊이 등이다.
이 문서를 쓰는 시점에 두 명령 모두 통과했다.

## 7. 알려진 문제와 남은 일

### 품질 확인 단계에서 고칠 것

- 고양이 모양이 거칠다. CC0 3D 모델로 바꿀 대상이다.
- 고양이가 회색으로 보인다. 카메라가 그늘진 쪽을 보기 때문이고 조명을 고쳐야 한다.
- 거실 안에서 카메라를 올리거나 멀리 빼면 지붕이 화면을 가린다. 실내에서는 카메라가 천장 아래에 머물러야 한다.
- 고양이가 뒤쪽 벽에 붙은 상태에서 시선을 돌리면 카메라가 벽 밖으로 나간다.
- 거실이 비어 있다.
- 바다는 단색 평면이고 움직이지 않는다.
- 빌드할 때 파일 크기가 500kB를 넘는다는 경고가 나온다. 7단계에서 파일을 나눈다.

### 지형에서 확인하지 못한 것

- 이전 세션의 브라우저 창이 숨겨진 상태여서 화면 확인이 제한되었다.
- 테라스에서 바다 쪽을 내려다본 화면에서 풀로 덮인 비탈과 그 아래의 야자수와 모래사장은 확인했다.
- 물가의 파도 거품과 활 모양의 만과 멀리 있는 곶은 화면으로 확인하지 못했다.
- 모래사장과 바다가 겹쳐 깜빡이던 문제는 물속 땅을 깊게 만들어서 고쳤다. 검사 스크립트는 통과했지만 화면으로는 확인하지 못했다.
- 사용자에게 화면을 보여 주고 사진과 다른 부분을 물어봐야 한다.

### 사용자가 답하지 않은 것

- `public/paw.svg`를 지울지. 지금은 쓰지 않는 이전 커서 파일이다.
- 토닥핏 저장소를 공개로 바꿀지. 비공개라서 `projects.ts`에 링크를 넣지 않았다.
- EFY에서 정책을 정한 사례. 맡은 일에 한 문장으로 넣고 싶어 한다.
- 좋아하는 소품의 설명이나 캡처.
- 중심 문장.

### 파일 내려받기

CC0 모델을 내려받을 때는 파일 이름과 출처와 용량을 사용자에게 알리고 확인을 받은 뒤에 내려받는다.
후보 출처는 Kenney와 Quaternius와 Poly Pizza다.

## 8. 사용자와 일하는 방식

사용자의 전역 규칙은 `~/.claude/CLAUDE.md`에 있다.
이 프로젝트에서 특히 지켜야 할 것만 적는다.

- 답은 한국어 `~입니다`체로 쓴다. 쉼표를 쓰지 않는다. 한 문장을 쓰고 줄을 바꾼다. 비유를 쓰지 않는다.
- 파일을 세 개 이상 바꾸거나 새 기능을 만들 때는 계획을 먼저 보여 주고 확인을 받는다.
- 코드를 고친 뒤에는 무엇을 왜 바꿨는지 초보자가 이해할 수 있게 설명하고 새로 쓴 문법에 한 줄 설명을 붙인다.
- `main`에 직접 커밋하지 않는다. 작업 브랜치에서 작업하고 PR로 합친다.
- push와 force push와 브랜치 삭제와 파일 삭제는 실행 전에 확인을 받는다. 단 머지가 끝난 로컬 작업 브랜치는 묻지 않고 지워도 된다고 사용자가 말했다.
- 커밋 메시지는 한국어로 쓰고 `feat:` 같은 종류를 앞에 붙인다. Claude 작성자 표시를 넣지 않는다.
- 사용자는 화면을 직접 조작해 보고 느낌을 말한다. 요청이 모호하면 화면을 찍어서 어느 방향을 말하는지 먼저 확인한다.
- 사용자의 설정을 약하게 만드는 변경은 먼저 묻는다. 이전 세션에서 절벽 높이를 묻지 않고 낮췄다가 지적을 받았다.

## 9. 다음 세션이 처음 할 일

1. 이 문서와 `src/scene` 폴더를 읽는다.
2. `npm run dev`로 화면을 띄우고 사용자에게 지형이 사진과 얼마나 비슷한지 물어본다.
3. `feat/house-scene`을 push하고 PR을 만들지 사용자에게 확인받는다.
4. 품질 확인 단계의 계획을 보여 준다. 고양이와 가구에 쓸 CC0 모델 후보를 찾아서 이름과 출처와 용량을 알려 준다.
